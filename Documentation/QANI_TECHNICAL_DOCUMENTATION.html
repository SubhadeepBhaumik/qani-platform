📋 System Overview

What is QANI?

QANI (Qualified AI Neural Intelligence) is an intelligent recruitment screening platform that uses conversational AI to automate candidate qualification.

Core Components

Frontend (Next.js 14) - React-based SPA for recruiter dashboard and candidate interface
Backend API (Node.js + Express + TypeScript) - RESTful API handling all business logic
Database (PostgreSQL) - Persistent storage for all application data
AI Engine (OpenAI GPT-4) - Conversational screening and analysis
Notifications (SendGrid) - Email notifications and communications

Key Features

  • AI-powered conversational screening with OpenAI
  • 5-area qualification scoring system
  • Automated decision routing (Progress/Review/Reject)
  • Real-time dashboard with analytics
  • Candidate application management
  • Email notifications integration
  • Audit logging for compliance
  • Role-based access control

🗄️ Database Schema

Core Models

Organisation

Field Type Description
id String (PK) Unique identifier
name String Organization name
type String? Type (RECRUITMENT_AGENCY, EMPLOYER, etc.)
industry String? Industry sector
subscriptionPlan String basic, premium, enterprise
status String active, paused, cancelled

User

Field Type Description
id String (PK) Unique identifier
organisationId String (FK) Reference to organisation
email String (UNIQUE) User email address
passwordHash String Bcrypt hashed password
firstName, lastName String User name
role String RECRUITER, CANDIDATE, ADMIN
status String active, inactive, suspended
emailVerified Boolean Email verification status

Role (Job Position)

Field Type Description
id String (PK) Unique identifier
organisationId String (FK) Reference to organisation
title String Job title (e.g., "Senior Developer")
location String? Job location
salaryMin, salaryMax Decimal? Salary range
employmentType String? full-time, part-time, contract
status String draft, active, closed
jdFileContent String? Job description

Application

Field Type Description
id String (PK) Unique identifier
organisationId String (FK) Reference to organisation
candidateId String (FK) Reference to candidate
roleId String (FK) Reference to job role
status String applied, screening, completed, progressed, rejected, review
appliedAt DateTime Application submission date

ScreeningSession

Field Type Description
id String (PK) Unique identifier
applicationId String (FK) Reference to application (UNIQUE)
status String active, completed, expired, paused
sessionToken String (UNIQUE) Security token for session
startedAt, completedAt DateTime? Session timestamps
currentStep Int Progress in screening (0-5)

CandidateScore

Field Type Description
applicationId String (FK) Reference to application
requirementId String (FK)? Reference to role requirement
qualificationArea String? location, salary, qualifications, work_rights, experience
rawScore Decimal Score before weighting (0-100)
weightedScore Decimal Score after weighting
weight Decimal Weight multiplier (0-1)
status String pass, fail, review, warning

RoutingDecision

Field Type Description
applicationId String (FK) Reference to application (UNIQUE)
outcome String progress, review, reject
overallScore Decimal Final qualification score (0-100)
reasonSummary String? Human-readable decision explanation
recruiterOverride Boolean Whether recruiter manually changed decision

All protected endpoints require a JWT token in the Authorization header:

🤖 AI Integration (OpenAI)

OpenAI Configuration

Model: gpt-4o-mini Max Tokens: 300 Temperature: 0.7 (natural conversation) System Prompt: Professional recruiter conducting screening interview

Screening Flow

1. Application submitted 2. Screening session created 3. System sends initial greeting via AI 4. Candidate answers questions in natural language 5. AI understands context and asks follow-ups 6. All responses recorded and analyzed 7. Answers extracted and scored 8. Final decision calculated 9. Candidate notified of results

5-Area Qualification Scoring

The AI screening evaluates candidates on:

1. Location Match

  • Does candidate location match job location?
  • Willing to relocate?
  • Remote work preference?

2. Salary Alignment

  • What is candidate's salary expectation?
  • Within budget range?
  • Negotiation range?

3. Qualifications

  • Does candidate have required certifications?
  • Education level appropriate?
  • Skills match job requirements?

4. Work Rights

  • Legal work rights in country?
  • Visa sponsorship needed?
  • Citizenship status?

5. Experience

  • Years of relevant experience?
  • Experience in similar roles?
  • Industry background match?

🔐 Security

Authentication & Authorization

  • JWT-based authentication
  • Bcryptjs password hashing (10 rounds)
  • Role-based access control (RECRUITER, CANDIDATE, ADMIN)
  • Secure token expiration (7 days)
  • Email verification for accounts

Data Protection

  • HTTPS/SSL encryption in transit
  • PostgreSQL at-rest encryption
  • Database access control with passwords
  • Environment variable management for secrets
  • Rate limiting on API endpoints

API Security

  • CORS configured for specific origins
  • Helmet.js for HTTP security headers
  • Express rate limiting
  • Input validation and sanitization
  • CSRF protection
